## 8. 발견된 이슈 갱신

- **serde_yaml deprecated**: v1.0.0-beta.2 마지막 릴리스 (2026-05-12). serde_yml 로 이전 필요. D-42 config TOML 통일 로 해결 (serde_yaml/serde_yml 의존 회피). tools/llm/context crate 에서 TOML 로 config 처리.
- **keychain 부재**: libsecret-1-dev + gnome-keyring apt install 완료 (D-41 prerequisite). W7 KeyringAuthStore 는 libsecret 부재 환경 graceful fallback (backend=None, BackendUnavailable 반환) — 절대 panic 안 함.
- **ANTHROPIC_API_KEY absent**: W7 llm crate mock test 로 우회. KeyringAuthStore 가 libsecret 부재에서도 safe.
- **Gitea PAT 설정 완료 (D-44)**: `~/.git-credentials` (chmod 600). Gitea credential helper 도 등록 완료. yklee 회전 권고.
- **rig-core 0.38.1 API 차이 (W7.2 R1 risk)**: `Text::new(text)` 생성자 사용, `completion_request(prompt).preamble(...).max_tokens(u64).send().await` 패턴. OpenAI 는 `CompletionsClient` (Chat Completions). Gemini `Client::new(api_key)`. 모두 plan agent + explore agent 로 source 확인 후 구현.
- **env::set_var/remove_var unsafe (Rust 2024)**: 테스트에서 `with_base`/`with_path` 메서드로 override, env mutation 회피.
- **context crate ↔ llm crate 분리 (W8)**: context 의 `Message`/`Role` 은 자체 정의 (llm 재방지, 의존성 방향 깨짐 방지). 다만 compression crate 가 llm 의존 (W9 — OK, 단방향).
- **W9.2 summarize block_in_place**: context 의 ContextManager 가 sync API 라서 async summarizer 를 blocking 호출. tokio runtime 필요. multi-thread flavor 로 테스트.
- **CCR double-lock deadlock (W9.3)**: retrieve 가 inner.lock() 두 번 → std::sync::Mutex deadlock. 한 번 lock + 두 lookup 으로 해결.
- **Kompress-base v1 단순화의 한계**: best-effort stemming 이 도메인 명사 ("anthropic") 도 stem. v1.5+ 에서 ONNX 또는 더 정교한 알고리즘 필요.
- **MockClient LIFO (W10.4)**: queue 가 LIFO (마지막 push 가 먼저 pop). FIFO 시뮬레이션 위해 push 시 reverse. W11 에서 v1.5 MockClient::push_fifo 추가 가능.
- **is_success word boundary (W10.4)**: response 가 orchestrator 의 "[LLM] ..." prefix + LLM content 결합 → "DONE" 단어가 prefix 가 아닌 중간에 위치. split_whitespace + DONE/SUCCESS word match.
- **tool name mismatch (W10.5)**: sub-agent 가 기대하는 도구 이름 ("Read"/"Grep"/"Glob", 대문자) vs tools crate 의 도구 이름 ("read"/"grep"/"glob_", 소문자). Orchestrator 가 WARN 로그 + dispatch 계속. W11 에서 tool name alias table 로 통일.
- **Orchestrator 의 LLM err swallow (W10.4)**: orchestrator.run() 이 llm.complete() Err 를 Ok(response+[LLM-error]) 로 wrap. LoopRunner 가 Err 못 받음 → max-iterations 도달 시 종료. v1.5 에서 LLM err fatal 옵션 추가.
