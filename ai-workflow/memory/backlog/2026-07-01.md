### 2.4 content hash algorithm 결정

| option | 장점 | 단점 |
|---|---|---|
| sha2 0.11 (workspace 존재) | 새 dep 없음 | xxhash spec 1:1 아님 |
| xxhash-rust 0.8 (신규 dep) | oh-my-pi 1:1 정합 | 새 dep + 빌드 시간 + |
| std::hash::DefaultHasher (Rust built-in) | dep 0 | deterministic ❌ (SipHash randomized per process) |

**결정 = sha2 truncate low 16-bit (4 hex uppercase)**. collision space = 65536, session-scope (단일 파일 ≤ 1MB) 에선 사실상 0. 4 hex `XX{low16:0>4X}` 형식 = oh-my-pi `low16.toString(16).padStart(HL_FILE_HASH_LENGTH, "0").toUpperCase()` 1:1.

### 2.5 normalize 결정

oh-my-pi 와 1:1: line 별 trailing `[ \t\r]+` trim. final newline 별도 보존. CRLF 는 v1 은 LF 만 (BOM/CRLF/Raw NUL 등은 D-105+ safety check 에서 추가).

### 8.2 implementation
**`myharness/crates/tools/src/edit.rs` (132 → 658 lines, +537 -11)**:

1. **`LineAnchoredEdit` struct** (private, serde Deserialize):
   - `start_line: usize` (1-indexed inclusive)
   - `end_line: usize` (1-indexed inclusive)
   - `expected_hash: String` (4-hex uppercase, Read v2 metadata `content_hash` 와 동일 형식)
   - `replacement: String` (multi-line 가능, `\n` 으로 split)

2. **`apply_line_replacement` helper** (private fn, `Result<String, String>`):
   - Validation: `start_line_1 >= 1` / `end_line_1 >= start_line_1` / `end_line_1 <= total_lines` (clear error msg)
   - Algorithm: `lines[..start-1] + repl_lines + lines[end..]` → `Vec<&str>` concat → `join('\n')` → trailing `\n` 보존
   - Empty replacement = 0 lines (delete semantics)
   - Non-empty replacement = `split('\n').collect()` (multi-line preserve)

3. **`EditTool::execute_line_anchored`** (private async method):
   - 순서: read → `compute_content_hash` → stale anchor reject → range check → `apply_line_replacement` → write → `compute_content_hash` 재계산 → metadata
   - Errors via `Err(ToolError::InvalidInput(...))` (기존 "old_string not found" 패턴 정합)
   - Stale anchor error message: `"stale anchor: file modified; re-read with \`Read\` tool (current hash XXX, expected YYY)"` (spec prefix + suffix 추가)

4. **`EditTool::execute` dispatch**:
   - `if input.get("line_anchored").is_some() { return self.execute_line_anchored(...); }` 위치: file_path parse 직후
   - **Legacy old_string branch (line 109-258)는 byte-identical** 유지
   - file_path `&str → String` clone 은 borrow checker 강제 (의미 변화 없음)

5. **변경 없음**: `lib.rs` / `content_hash.rs` / `read.rs` / `error.rs` / `tool.rs` / `Cargo.toml` 모두 그대로 (LineAnchoredEdit internal, sha2 기존 dep 재사용)

## 11. 세션 D-107 (pure_edit mode — multi-section insert/delete)

### 11.1 why
yklee 결정 = (b) D-106+ pure insert/delete. oh-my-pi `insert before/after N` + `delete N..M` + `insert head/tail` 의미론. D-105 line_anchored 가 "기존 line N..M 통째 교체" 만 가능했다면, D-107 은 **순수 추가/삭제** 를 multi-section 으로 한 patch 에 묶음.

### 11.2 설계
- 입력 스키마 (D-105 와 통일, stale-anchor gate 동일):
  ```json
  {
    "file_path": "...",
    "pure_edit": {
      "expected_hash": "A1B2",
      "insertions": [
        {"op": "insert_before", "line": 5, "content": "..."},
        {"op": "insert_after",  "line": 7, "content": "..."},
        {"op": "insert_head",   "content": "..."},
        {"op": "insert_tail",   "content": "..."},
        {"op": "insert_after_block", "line": 3, "content": "..."}
      ],
      "deletions": [
        {"start_line": 5, "end_line": 7},
        {"start_line": 9, "end_line": 9}
      ]
    }
  }
  ```
- **multi-section atomic**: 모든 op 를 line-DESCENDING 으로 정렬 후 순차 적용. high anchor op 가 low anchor op 의 anchor 를 shift 시키지 않음. priority: Delete(0) > After(1) > Before(2) > Head|Tail(3).
- **stale-anchor gate**: v1.5 safe-by-default — `expected_hash` 필수 (없으면 reject). pure_edit 는 file mutation 만 하므로 gate 가 critical.
- **insert_after_block**: D-106 `resolve_block_span` 재사용. Rust only (D-106 v1.5 scope 정합).
- **non-rust with insert_after_block**: explicit reject (`tree-sitter grammar for .{ext} not yet supported`).
- **return metadata**: `{mode: "pure_edit", applied: [{op, line|start_line, lines_added|lines_removed}], old_hash, new_hash}`.
